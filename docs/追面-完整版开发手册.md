# 「追面」完整版开发手册（TRAE 逐步执行）

> 追问式模拟面试 · 完整版 · 提交截止 **11.23**
> 纪律：每完成一个 Step 就 `git commit`；**每晚 23:00 打 tag，保证项目随时处于"可提交"状态**。
> 优先级铁律：**追问引擎的质量 > 一切功能**。任何功能出问题都不能影响核心闭环可用。

## 一、产品定义（完整版）

**一句话**：贴一段你的项目经历（或上传简历），AI 面试官像真面试一样层层追问，逐题告诉你"哪句话被问穿了、该怎么改"，最后生成复盘报告 + 7 天提升计划，支持重练与两轮对比。

### 功能清单（6 大模块，全部实现）

| 模块 | 功能点 |
|---|---|
| A 输入 | 文本粘贴 · PDF/Word 简历上传解析（提取项目经历可勾选） · 7 类岗位预设模板 + 自定义 JD 解析 |
| B 面试引擎 | 4 题追问状态机（每题最多 2 层追问） · 岗位能力锚定 · 题库种子题 · 保护机制（连答不上给提示换题） |
| C 语音 | 语音输入 STT（录音→转文字） · 问题朗读 TTS（高质量 API + 浏览器兜底） |
| D 反馈与报告 | 逐题 STAR 评分 + 原句 vs 改写 · 五维雷达图 · 失分模式 · 7 天提升计划（可勾选） · 自检清单 · AI 改写项目经历 · 导出长图 |
| E 练习闭环 | 同题重练（低分题） · 两轮对比（雷达叠加 + 逐题分差 + LLM 总结） · 历史记录页 |
| F 账号与数据 | Supabase 匿名会话（免注册可用） · 一键升级邮箱账号同步历史 · 数据删除按钮（合规） · localStorage 兜底 |

### 明确不做（防蔓延）
多语言、视频面试、真题付费库、简历完整评分、小程序端、管理后台。

## 二、技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | Next.js 14 App Router + TypeScript + Tailwind + shadcn/ui | 前后端一体，API Route 藏 key |
| LLM | **硅基流动 SiliconFlow 一家全包**（DeepSeek-V3 文本 + SenseVoice 语音识别 + CosyVoice 语音合成），全部 OpenAI 兼容 REST | 一个 key 搞定 LLM/STT/TTS，降本管理成本；备选：DeepSeek 官方 + 火山引擎 |
| 数据库/账号 | Supabase（匿名登录 + Postgres + RLS） | 免注册可用，升级账号同步历史 |
| 图表/导出 | recharts + html2canvas | 雷达图 + 长图导出 |
| 文件解析 | pdf-parse（PDF）/ mammoth（docx），服务端 | 扫描件无文本要友好提示 |
| 部署 | 腾讯云 EdgeOne Pages（国内访问稳），备选 Vercel | 验收标准：手机 4G 热点丝滑打开 |

**环境变量清单**（`.env.local`，key 全部只在服务端用）：
```
LLM_API_KEY=（硅基流动 key）
LLM_BASE_URL=https://api.siliconflow.cn/v1
LLM_MODEL=deepseek-ai/DeepSeek-V3
SF_API_KEY=（同上，语音用）
ASR_MODEL=FunAudioLLM/SenseVoiceSmall
TTS_MODEL=FunAudioLLM/CosyVoice2-0.25B
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
```
（模型名以平台文档为准；LLM 换供应商只改 BASE_URL/MODEL。）

## 三、核心 Prompt 资产（`lib/prompts.ts`，产品灵魂）

### ① 追问面试官系统提示词

```
你是「追问面试官」，严格但友善的校招面试官，专精深挖应届生项目经历。
当前岗位方向：{{track}}；岗位关键能力：{{capabilities}}；可参考考察重点：{{seedQuestions}}。

规则：
1. 共 4 题，一次只问一个；每题必须引用候选人项目经历中的原句片段作为锚点(anchor)。
2. 第一题选项目中最核心、描述最模糊的部分；后续题目覆盖不同能力锚点，不重复同一片段。
3. 追问优先级：量化结果缺失 > 个人贡献边界模糊 > 技术选型理由 > 协作与冲突 > 失败与反思。
4. 回答含糊（无数据/无方法/无验证，"参与了""负责"类）必须追问，每题最多 2 层。
5. 候选人连续两次答不上：给一句 hint，进入下一题。
6. 结合岗位能力追问，能区分"背来的项目"和"真做过的项目"。
7. 语气：先认可一个具体点，再追问一个具体缺口；不客套、不羞辱、不评价简历排版。
8. 严格输出 JSON：{"type":"question|followup|wrapup","anchor":"原句片段","question":"...","hint":"答不上时的提示，可空"}
```

### ② 逐题评分提示词

```
基于刚才这一轮问答，输出严格 JSON：
{"score":0到10,"star":{"situation":"评语","task":"评语","action":"评语","result":"评语"},
"quotes":[{"said":"候选人原句","issue":"这句话的问题","rewrite":"改写示例"}],
"missed":["面试官想听到但你没说的点"],
"one_tip":"最重要的一条改进"}
quotes 至少 2 条；rewrite 必须可背诵、有数字感。
```

### ③ 总复盘提示词

```
汇总所有题目的评分与反馈，输出严格 JSON：
{"radar":{"事实与数据":0-5,"个人贡献":0-5,"技术深度":0-5,"结果导向":0-5,"逻辑表达":0-5},
"patterns":["3 个反复出现的失分模式，每个一句话说清"],
"plan_7d":[{"day":1,"action":"一个 30 分钟内可完成的具体动作"}，共 7 条],
"checklist":["下次面试前的 5 条自检"]}
```

### ④ 简历提取提示词

```
从以下简历文本中提取所有项目/实习经历，每段保留原始细节，不要润色。输出严格 JSON：
{"projects":[{"name":"项目或实习名","text":"原文段落(≤300字)","highlights":["可能被面试官深挖的点"]}]}
简历文本：{{resume}}
```

### ⑤ 经历改写提示词

```
把候选人这段项目经历改写为"面试友好版"：STAR 完整、每句可被追问出细节、
量化表述用「建议补充：xx」占位提示而不是编造数字；不得虚构本人没提过的成绩。
输出严格 JSON：{"rewrite":"...","notes":["3 条修改理由"]}
原文：{{text}}
```

**验收标准**：拿你自己的真实经历跑一遍，追问要"扎心但不羞辱"。调这三个面试类 prompt 的时间 ≥ 总时间 20%。

## 四、数据库 Schema（Supabase SQL Editor 执行）

```sql
create table interviews (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users default auth.uid(),
  project_text text not null,
  track text not null,
  jd_text text,
  rounds jsonb default '[]',
  report jsonb,
  status text default 'in_progress',
  created_at timestamptz default now()
);
alter table interviews enable row level security;
create policy "own rows" on interviews for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);
```

## 五、TRAE 逐步执行手册（16 步）

> 用法：每步单独开 TRAE 会话（方便留证：**截图 + 记录 Session ID**，报名硬要求）。
> Builder 模式一次只给一个目标；先要计划再放行写代码；报错原样贴回去。

### Step 0｜准备（30 分钟，不用 TRAE）
- 注册硅基流动（充 ¥20）、Supabase（新建项目）、EdgeOne Pages 账号
- Node 18+；TRAE 新建项目文件夹 `zhui-mian`；`git init`
- 建立留证习惯：Step 1/3/4/7 的会话最有展示价值

### Step 1｜骨架
```
用 Next.js 14 App Router + TypeScript + Tailwind + shadcn/ui 创建项目「追面」。
页面：/（落地页：标题"别让「我负责了」毁掉你的项目经历"；项目经历粘贴文本框 + 岗位下拉 +
"上传简历"按钮 + 醒目按钮"用示例项目 30 秒体验"）；/interview 面试对话页；/report 复盘报告页；
/history 历史记录页。主色 #2563EB，白底极简，移动端优先。先输出实施计划，我确认后再写代码。
```
验收：`npm run dev` 四个页面可跳转，手机宽度下布局不塌。

### Step 2｜类型与服务层
```
lib/types.ts 定义类型：ProjectInput{projectText,track,jdText,source}；
Round{index,question,anchor,answer,followups[],feedback?}；
InterviewSession{id,userId?,input,rounds[],status,startedAt,finishedAt}；
Feedback{score,star,quotes,missed,oneTip}；
Report{radar,patterns,plan7d,checklist}；TrackPreset{id,name,capabilities,seedQuestions}。
app/api/chat/route.ts：POST 接收 {messages}，OpenAI 兼容 SDK 调用 LLM
（env: LLM_API_KEY / LLM_BASE_URL / LLM_MODEL），返回 SSE 流式；30s 超时、失败重试 1 次、
key 缺失返回明确错误。所有 key 只存在于服务端。
```
验收：写个临时按钮调 /api/chat，能流出 DeepSeek 回复。

### Step 3｜追问引擎（灵魂步骤，单独会话留证）
```
lib/prompts.ts 写入我提供的 5 个提示词（我贴给你）。
lib/engine.ts 实现面试状态机：start → question(引用原文 anchor) → 用户回答 →
含糊则 followup（每题最多 2 层）→ 每题结束调评分 prompt → 4 题结束调总复盘 prompt。
追问需结合岗位能力锚点与题库种子题。所有 LLM JSON 输出做解析容错：
失败重试 1 次，再失败降级为纯文本追问，绝不能让面试中断。
```
验收：命令行跑通 4 题全流程；拿两段不同质量的经历测试，追问明显不同。

### Step 4｜面试页 UI
```
完成 /interview：AI 问题卡片独立样式并高亮 anchor（"面试官抓住了这句：……"）；
追问卡片用不同视觉样式；每题结束插入反馈卡（分数、原句 vs 改写左右对照、oneTip 强调）；
顶部进度"第 x/4 题"；AI 消息打字机流式渲染；底部输入框 Enter 发送、Shift+Enter 换行、
语音按钮占位；"跳过此题""结束并看报告"按钮；对话状态持久化 localStorage，刷新不丢。
```
验收：手机上完整走一轮，无布局错乱。

### Step 5｜语音输入 STT
```
实现语音输入：前端 MediaRecorder 录音（点击开始/停止，录音音量动画），blob 以 FormData
发送到 app/api/stt/route.ts；服务端调用硅基流动 /v1/audio/transcriptions
（模型 ASR_MODEL，env: SF_API_KEY），返回文字自动填入输入框；录音≤60 秒；
无麦克风权限或识别失败时明确提示，并自动降级为文字输入（按钮置灰但保留）。
```
验收：安静环境中文识别准确；断网/无权限不崩。

### Step 6｜TTS 朗读
```
面试官每个问题卡片加朗读按钮 + "自动朗读"全局开关（存 localStorage）：
优先调用 app/api/tts/route.ts（硅基流动 TTS 模型 TTS_MODEL，返回音频自动播放），
失败降级浏览器 speechSynthesis（zh-CN），两级都失败静默隐藏按钮。
```
验收：问题能朗读；静音环境操作不报错。

### Step 7｜报告页
```
完成 /report：recharts 五维雷达图；patterns 编号卡片；7 天提升计划可勾选（存 localStorage）；
自检清单；"AI 改写这段项目经历"按钮调 /api/rewrite（用改写 prompt），展示改写文本与修改理由、
可复制；html2canvas 一键导出长图；"重练最弱两题"按钮（取最低分题目重建 session 跳 /interview）。
直接访问无数据时重定向回首页。
```
验收：报告完整渲染；导出长图清晰。

### Step 8｜简历上传解析
```
落地页"上传简历"：支持 .pdf/.docx、≤5MB，前端校验后发 /api/parse-resume；
服务端 pdf-parse（PDF）/ mammoth（docx）提取纯文本，无文本（扫描件）时提示"请粘贴文字版"；
再用简历提取 prompt 让 LLM 输出 JSON{projects:[{name,text,highlights}]}，
前端列出候选项目让用户勾选 + 可编辑，选定后填入输入框进入面试；解析全程有进度状态。
```
验收：一份真实文字版 PDF 全流程成功；扫描件走降级提示。

### Step 9｜岗位模板 + 自定义 JD
```
lib/presets.ts：7 个岗位模板（后端/前端/算法/产品/运营/数据/通用），每个含
capabilities[]（能力锚点）与 seedQuestions[]（各 6 道校招场景题）。
自定义 JD 粘贴后经 /api/parse-jd 用 LLM 提取{capabilities,focusPoints}，与模板能力合并，
作为追问锚定输入传给面试官 prompt。
```
验收：同一项目经历分别选"后端"和"产品"，追问侧重点明显不同。

### Step 10｜Supabase 账号与历史
```
集成 Supabase（@supabase/ssr）：匿名登录自动创建会话；interviews 表（schema 见手册），
RLS 仅本人读写；面试结束自动保存；/history 列出历史（时间、岗位、总分），可打开报告或重练；
"升级为正式账号"（邮箱 magic link）后匿名数据自动归属新账号；设置里提供"删除我的全部数据"；
未登录或网络失败时一切功能仍走 localStorage 可用。
```
验收：无注册完整可用；升级账号后历史不丢；删除按钮生效。

### Step 11｜重练对比
```
重练完成后 /report 顶部显示两轮对比：雷达图叠加对比、逐题分差（↑↓ 颜色区分）、
LLM 生成的一段"这两轮你改进了什么 / 仍需注意什么"。/history 支持任选两条记录对比。
```
验收：重练一轮后对比数据正确渲染。

### Step 12｜演示数据与全站打磨
```
落地页"用示例项目 30 秒体验"预填："参与开发校园二手交易小程序，负责后端接口开发，
使用 Redis 优化了查询性能，用户反馈良好" + 岗位"后端开发-校招"。
全局：ErrorBoundary 不白屏、加载态骨架屏、断网重试提示、空态设计；
移动端自查（键盘弹出遮挡、滚动、触摸目标≥44px）；npm run build 零报错。
```
验收：全新手机浏览器访客 3 分钟内无卡点走完"体验→面试→报告"。

### Step 13｜部署
```
准备生产部署：确认 env 清单；输出 EdgeOne Pages 部署步骤与备选 Vercel 步骤；
写 README（本地运行 + 部署 + 环境变量说明）。
```
验收：线上域名手机 4G 热点全流程跑通（这一步不过，当晚不许睡）。
