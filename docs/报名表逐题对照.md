### 题 13【粘贴】详细介绍（三问结构，评审重点）

```
1、核心功能与亮点：
①追问式模拟面试：AI 面试官引用简历原文逐字锚点提问（页面高亮「面试官注意到了你项目经历里的这句」），含糊回答自动追问（每题最多两层），连续答不上给提示换题；7 套岗位模板与自定义 JD 决定考察方向。相比"生成一堆通用面试题"的同类工具，它的每个问题都长在用户自己的经历上。
②逐题反馈：每题作答后立即出评分（0-10）、STAR 四维评语、原句 vs 改写对照、最重要的一条改进。改写只重组用户已陈述的事实，缺失数据标「待补充」，不编造。
③复盘报告：五维能力雷达、失分模式、可勾选的 7 天提升计划（随面试主题自适应）、面试前自检清单、AI 改写项目经历、一键导出长图。
④同题重练与对比：从报告发起低分题重练，重练报告与原轮雷达叠加、逐题分差、改进总结——练完看得见进步。
⑤语音输入与朗读：录音转文字填入回答框（可编辑后发送）；问题朗读（手动/自动），接口失败自动降级浏览器合成。
⑥免注册与账号：匿名身份自动创建即可开始；历史记录云端保存；邮箱升级后数据归属正式账号；一键删除全部数据。

2、TRAE 提供的具体帮助（三个实例）：
①追问引擎的事实边界：TRAE 协助实现了"锚点必须逐字出现在简历原文、引用必须逐字来自用户回答"的校验体系，并通过多轮对话修复了"改写整句退化为待补充""把 JD 要求当成候选人经历"等问题——最终实现评分敢给 0-10 全区间、改写不编造数字。
②云同步与断网降级：TRAE 协助完成 Supabase 匿名登录、行级安全、断网提示与联网自动补传——云端不可用时全部功能走本地存储，恢复后自动重试。
③示例多样性：用户反馈"全是 Redis 问题"后，TRAE 协助扩充示例项目为 4 个方向锚点并调整提问策略，实测三场面试首题锚点各不相同。

3、印象最深的经历：
部署上线次日，一位要面试入职的朋友通过公网地址完成了真实面试。他的回答很含糊（"接口返回延迟高"），AI 连续两层追问量化细节，最后给出 3/10 的评分——改写示例引用了他自己说的"10 秒/20 秒"数据，缺失部分标「待补充」。他看完说"能看到一些自己的不足"，还主动把链接发给了同事。同一天，三名独立测试员的报告指出示例面试"只问 Redis"——我们随即把示例项目扩充为 4 个方向锚点，实测三场面试首题各不相同。这两件事让我确认：产品最有价值的部分（追问的事实边界与多样性）恰好也是最需要严格工程纪律的部分，而这正是 TRAE 全程协作才能在两天内做到的。
```
